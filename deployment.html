Deployment Strategies

Most educator-built tools do not need a complex stack. Start with the simplest home that matches the risk and audience.

Canvas link

Best for drafts and collaboration

Use this when you are still building, testing with colleagues, or showing the process. It is the lowest-friction option, but it is not the cleanest public home for a finished tool.

Google Sites

Best for simple tools inside a familiar school ecosystem

Great when the app is a single self-contained HTML embed and your audience already uses the Google Site. Keep it simple: no student data collection, no external accounts, no backend assumptions.

GitHub Pages

Best for a permanent public web page

Free static hosting for HTML, CSS, JavaScript, and assets. Good for portfolios, resource hubs, interactive demos, and multi-file projects that do not need private server-side data.

IDE + agent

Best when the project outgrows copy-paste

Use VS Code with an agent like Codex or Claude when you need folders, separate files, refactors, version control, and a more durable development workflow.

Decision rule

Do not overbuild.

Choose the least complex path that lets the right people use the tool safely.
