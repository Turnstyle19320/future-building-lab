After it works

Where does this thing live?

Your project is a folder of files. That folder can sit on your desktop, or it can have its own address on the real internet. Same files. Different home.

The simplest version

Save it on your desktop. Double-click it.

When the AI gives you an HTML file, you don't need a server. You don't need GitHub. You don't need anything except the file.

Save the file to your desktop. Double-click it. Your browser opens it like any other web page. That's already a working web app — it just isn't on the internet yet.

taskFlow started exactly like this. So did everything else I've built.

file:///Users/you/Desktop/my-tool/index.html

Skill first, infrastructure second.

Some of the publishing paths on this page may not be available through a school account yet. That is normal. The useful move is to build the skill, prototype inside the tools you do have, and understand enough of the larger landscape to ask better questions when your district is ready.

Getting it in front of someone else

Two ways to share it.

Pick the one that fits how you already share things with students or colleagues.

Path A — familiar

Embed it in a Google Site.

If you already use Google Sites for class pages, this is the gentlest next step. Drop your tool into a page students already visit.

sites.google.com/yourschool/unit-3

Path B — real URL

Publish it with GitHub Pages.

If you want the tool to have its own home on the internet — a link you can send anyone, that outlives the class page — this is one path. Your school account may not allow it yet, and that is an infrastructure issue, not a reason to stop building the skill.

yourname.github.io/reflection-spinner

Quick how: Push your folder to a GitHub repo, open Settings → Pages, choose the main branch, save. Your URL is live in a minute.

Which to start with.

If the tool belongs inside a class page, embed it. If your district blocks GitHub, Cloudflare, or similar services, stay with what you can access and keep learning what else is possible. A tool can move later when the infrastructure catches up.

For context, not today

The road keeps going.

Most teacher-built tools never need anything beyond the two paths above. The rest is useful to know, even when local permissions make it a later conversation.

When you want a tool that remembers things across devices, syncs in real time, has user accounts, or stores actual records — you've moved into "real app" territory. That usually means a folder of files instead of one, a code editor like VS Code, an AI coding helper like Claude Code or Cursor, and eventually some kind of storage layer (which is the next section).

None of that is necessary today. The full five-stage path is on the ladder on From Idea to Folder.

It sounds like the deep end. It's actually the time-saver.
  • No more copy-paste loop. Claude Code edits your files directly. You stop ferrying code in and out of a chat window every iteration.
  • It sees the whole project. Reads across index.html, style.css, and script.js at once and keeps them in sync — Gemini Canvas only knows about one file at a time.
  • Version history is built in. Every save is tracked. Roll back a broken change without losing the work that was good.
  • One afternoon to set up. Download VS Code. Run one command to install Claude Code. Point it at your folder. That's it.
A separate question

Where the data goes matters more than how the page looks.

Sharing a page and storing data are two different decisions. A public page can collect nothing. A polished-looking tool can quietly send everything to a database.

Lowest stakes

No saved data, or local only.

The page runs in the browser and either forgets everything when closed, or saves a few things to localStorage on that one device. No server, no account, no data leaves the computer.

Good for: flashcards, timers, simulations, personal checklists, classroom prompt generators.

The clever middle

Google Apps Script + your Drive.

A free Google trick. Your tool talks to a file in your own Google Drive through Apps Script. It syncs across your devices without setting up a database or paying for a service. This is exactly how taskFlow works.

Good for: personal tools you want on your phone and laptop. The prompt that got me started: "What's the simplest way to sync this without a complicated cloud setup, using tools I already have?"

Real cloud territory

A cloud database.

Firebase, Supabase, or another backend. Necessary when multiple users need to share live data, when you need accounts, or when the tool stores records that have to persist properly.

Important: once student data is involved, this is where district approval and FERPA become real. Read Student Data before you go here.
