After it works

Share and Store

The next question is not "How do I deploy?" The next question is: who needs to use this, and where does the data live?

Decision path

Pick the simplest safe home.

Beginners do not need every hosting option. They need a clear ladder from "I made something" to "people can use it safely."

1. Keep it in the AI workspace

Use when: it is still a rough draft, you are learning, or you want a colleague to see the build process.

Examples: Gemini Canvas share link, ChatGPT conversation, Claude artifact, or another AI workspace preview.

Limit: this is not always the best final home. It may depend on account access and may not feel like a clean classroom resource.

2. Embed a simple tool in Google Sites or an LMS

Use when: the tool is one self-contained HTML file and belongs near existing class materials.

Good for: flashcards, calculators, practice tools, reflection prompts, simple dashboards, and no-login prototypes.

Limit: embedding is best when the tool does not need server-side data, accounts, uploads, or shared records.

3. Publish a static site with GitHub Pages

Use when: you want a permanent public URL or the project has multiple files.

Works well with:

my-tool/
  index.html
  style.css
  script.js
  assets/
    image.png

Limit: GitHub Pages publishes static files. It is not a private database or roster system.

4. Move into VS Code with an AI coding agent

Use when: copy-paste editing starts to break down, you need multiple files, or you want version history.

Good for: Codex, Claude Code, or another agent working across a real project folder.

Teacher-friendly rule: move to an IDE when you are maintaining a project, not when you are just trying to get the first version working.

5. Add a server only when the tool needs one

Use when: devices need to communicate live, users need join codes, or data needs to sync across devices.

Examples: a Node.js app with WebSockets for a live activity, a Cloudflare Worker for a lightweight serverless endpoint, Firebase for authentication or database-backed apps.

Limit: servers and databases introduce privacy, security, account, retention, and district approval questions. This is not where beginners need to start.

Storage ladder

Saving data changes the project.

A tool can look the same on screen while being very different underneath. The difference is where the data goes.

No storage

Safest first version

The page runs, teaches, calculates, or simulates, then forgets everything.

localStorage

Saved on this device

Useful for demos and personal progress on one browser. Not a secure shared record.

Cloud database

Shared across devices

Useful for real apps, but student data now needs governance and district review.
