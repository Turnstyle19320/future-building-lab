Vibe Coding for Educators

This is a field guide for making small web tools with AI. Start with what you want the learner or teacher to experience, then ask the AI to build the page that supports it.

First mental model

A web app is usually three things.

Structure, style, and behavior. You do not have to memorize code. You just need enough vocabulary to ask for the next useful change.

What the AI is building

Plain language first. Code second.

Each layer has a job. If something looks wrong, ask about CSS. If something does not respond, ask about JavaScript. If the page is missing a section, ask about HTML.

HTML creates the pieces on the page

HTML is the page structure: title, directions, input box, button, and the area where evidence cards appear.

Prompt move: "Create the HTML structure first. Include a title, instructions, a form, and a results area."

<h1>Evidence of Impact</h1>
<p>Add one example of learning or contribution.</p>
<textarea></textarea>
<button>Add Evidence</button>
<section id="entries"></section>
CSS changes how it feels

CSS controls the visual design: spacing, colors, fonts, cards, shadows, and mobile layout.

Prompt move: "Make this feel like a calm professional classroom tool, not a worksheet or a game."

JavaScript makes it respond

JavaScript is the behavior: click a button, save an entry, update a count, flip a card, filter a list, or draw something.

Prompt move: "When the user clicks Add Evidence, create a new card and update the summary counts."

button.addEventListener("click", () => {
  // read the form
  // create a card
  // update the summary
});

Prompt recipes

Ask for one move at a time.

Copy these when you are stuck. The pattern is: describe the audience, describe the job, describe the interaction, then ask for a complete first version.

Simple classroom tool

"Create a single-file HTML tool for vocabulary practice. Students should see one term at a time, guess the definition, click to reveal the answer, and track how many they got right. Make it clean and readable for middle school."

Interactive dashboard

"Create a dashboard where students can add evidence of learning, tag it as growth, revision, contribution, collaboration, or reflection, and see a simple summary. Store entries in localStorage for this demo."

Better styling

"This works, but it looks generic. Redesign it for teachers. Use warm neutral colors, clear hierarchy, readable font sizes, strong spacing, and buttons that are easy to find. Do not make it childish."

Debugging

"The Add button does not create a new card. Read the code, explain the likely cause in plain language, then give me a corrected full file."

When you are ready

Single file, folder, or real app?

Do not start with a complex setup. Start with the smallest version that lets you test the idea.

One HTML file

Best for first prototypes, Google Sites embeds, and tools that do one job.

Project folder

Best when you have separate HTML, CSS, JavaScript, and images.

VS Code + agent

Best when you need help managing multiple files, debugging, and publishing.

Server or database

Best only when the tool needs live collaboration, join codes, accounts, or cloud storage.
