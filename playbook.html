Mental model

Three layers, three different problems.

Every web page is built from three things stacked together. You don't have to write any of them — the AI does that. You just need to know which one to ask about when something is off.

The diagnostic move.
  • If a section is missing from the page, ask about HTML.
  • If something looks wrong or feels generic, ask about CSS.
  • If a button or input doesn't do anything when you interact with it, ask about JavaScript.
Layer 1

HTML — the pieces on the page.

HTML is the structure. Title, paragraph, input box, button, image, list. Everything you see is an HTML element.

Think of HTML as the bones. The AI writes it in tags that look like <h1> for headings, <p> for paragraphs, <button> for clickable things. You don't need to memorize them. You just need to recognize them when you see them.

What to ask for: "Create the structure first. I need a title, a short instruction, a text area for input, a submit button, and a section below where the entries will appear."

my-tool.html
<h1>Evidence of Impact</h1>
<p>Add one example.</p>
<textarea></textarea>
<button>Add Evidence</button>
<section id="entries"></section>
Layer 2

CSS — how it looks and feels.

CSS controls everything visual: colors, fonts, spacing, rounded corners, shadows, layout. Same HTML, different CSS — completely different experience.

Same HTML. Different CSS.

The two boxes above contain the exact same headings, the exact same words, and the exact same buttons. CSS is everything that makes the right one feel like a tool you'd actually use. CSS is also what made this site look the way it does — a few hours ago it was dark and slogan-heavy. Same content. Different CSS. Different world.

What to ask for: "Restyle this. Warm cream background, terracotta and sage accents, Newsreader serif for headings, Space Grotesk for body text. Generous spacing. Rounded corners. Calm and professional — not childish, not corporate."

Layer 3

JavaScript — making the page respond.

JavaScript runs when you click, type, or hover. It listens for things and changes the page in response.

Try it.

Click the button below. The way the message appears — that's JavaScript. It listened for your click and changed what's on the page.

You clicked. That's it. That's the whole idea — wait for something to happen, then change something on the page.

That's all JavaScript is, at its simplest: listen for an action, then change something. The fancy stuff is just more of that, stacked.

What to ask for: "When the user clicks Add Evidence, read what's in the textarea, create a new card on the page with that text, and clear the textarea so they can add another."

script.js
const button = document.getElementById("js-demo-btn");
const message = document.getElementById("js-demo-msg");

button.addEventListener("click", () => {
  message.classList.toggle("visible");
});
Tell AI to use these

The vibe coder's toolkit.

Each of these is a free, well-known building block. Naming them in your prompt makes a real difference in what you get back.

For how it looks

Tailwind CSS

A CSS shorthand. Instead of writing styles in a separate file, you add little class names like bg-amber-50 directly in your HTML.

class="bg-orange-600 text-white px-4 py-2 rounded-full font-bold"

Tell the AI: "Use Tailwind CSS for all styling."

Lucide Icons

A free library of clean modern icons. Tiny addition, huge effect on how polished a tool feels.

Tell the AI: "Use Lucide icons. Add a book icon next to the Study button."

Google Fonts

A free library of professional fonts you load with one line of code. This site uses Newsreader for headings and Space Grotesk for body.

Hello. Newsreader

Tell the AI: "Use Google Fonts. Load Inter for body text."

Hero Patterns

A free library of subtle SVG background patterns. Drop one into your CSS for instant visual texture, no image file required.

Tell the AI: "Add a subtle Hero Patterns SVG background. Keep it light so text stays readable."

For moments and feedback

Animate.css

A library of pre-made entrance, exit, and attention animations. Add a class name like animate__bounce and the element moves.

Tell the AI: "Use Animate.css. Bounce the score when it goes up."

canvas-confetti

Drops confetti on the page in two lines of JavaScript. Tiny library, huge emotional payoff — perfect for "you got it right" or "task complete."

Tell the AI: "Use canvas-confetti to fire confetti when the user gets the answer right."

Howler.js

A small library for playing audio in the browser — click chimes, success dings, ambient background music. Works on every device.

You bring the audio file (or grab a free one from somewhere like Freesound). Howler handles the rest.

Tell the AI: "Use Howler.js to play a soft chime when the form submits."

For what it does

localStorage

A way for a web page to remember things between visits — on the same browser, on the same device.

Lets your tool persist user input without a server or a database. Good for personal tools and one-device demos.

Tell the AI: "Save entries to localStorage and reload them when the page opens."

Apps Script + Drive

A free Google trick. Your web page talks to a file in your own Google Drive through Apps Script.

The simplest way to sync data across your own devices without setting up a real cloud database. This is exactly what taskFlow uses.

The prompt: "What's the simplest way to sync this across my devices without a complicated cloud setup, using tools I already have?"

Chart.js

A simple JavaScript library for making charts — bar, line, pie, scatter. Animated and interactive out of the box.

Tell the AI: "Use Chart.js to show the results as a bar chart."

EmailJS

Lets a form on your page send an email — no backend, no server. Submitted form data lands in your inbox.

Great for feedback forms, parent-contact submissions, "ask the teacher a question." Free tier covers most classroom use.

Tell the AI: "Use EmailJS so the feedback form sends to my email instead of saving locally."

PeerJS

A small JS library that connects browsers directly to each other for real-time sync. Built on WebRTC.

The host generates a room code, others join with it, and data flows peer-to-peer. PeerJS hosts the matchmaking server for free — you don't run anything on the backend. See it running →

Tell the AI: "Use PeerJS. Host generates a room code; clients join with it; data syncs live between browsers."

Beyond text and buttons

When you need pictures, games, or diagrams.

HTML buttons and text inputs handle most classroom tools. When you need something that draws shapes or moves, name one of these two ingredients in your prompt.

First, the confusing word.

"Gemini Canvas" is the environment on gemini.google.com — the chat plus the live preview. <canvas> is a specific HTML element you can put inside your page. Same word, two completely different things. From here, "canvas" means the HTML element.

SVG — shapes drawn with code

For diagrams, charts, and turn-based games.

SVG draws with code: circles, lines, paths, text. Each shape is its own object you can click, color, or animate. Stays sharp at any size.

A diagram built with SVG
  • Best for diagrams, charts, board games, drawing apps.
  • Every shape is clickable — easy to make interactive.
  • UnscriptED.fit is built on SVG.

Tell the AI: "Use SVG to draw this — not <canvas>."

<canvas> — fast pixel surface

For action games and lots of moving things.

A blank rectangle inside your page that JavaScript paints on, pixel by pixel. Made to redraw thousands of times per second.

A game built with <canvas>
Score: 3
  • Best for arcade-style games, physics, particle effects.
  • Fast — but pixels, not clickable shapes.
  • Three.js builds on canvas for 3D graphics.

Tell the AI: "Use an HTML <canvas> element. Draw and animate with JavaScript."

Two ready-made prompts for these are in the recipes further down — one for an SVG board game, one for a <canvas> game.

Putting it together

How to turn the AI's code into actual files.

The AI gives you code. You need to get that code into a file (or files) on your computer. The whole journey is four moves.

1

Copy from Canvas

In Gemini, Claude, or ChatGPT, click the copy button on the code block the AI gave you.

2

Open a text editor

TextEdit on Mac, Notepad on Windows, or VS Code if you have it. Any plain-text editor works.

3

Paste and save

Paste the code. Save the file with the right name and extension (see the paper-cut below).

4

Double-click it

The file opens in your browser. That's your tool, running on your computer.

Path A — easiest

Everything in one .html file.

HTML, CSS, and JavaScript all live inside the same file. The CSS goes inside a <style> tag at the top. The JavaScript goes inside a <script> tag at the bottom. One file. Everything included.

What it looks like on your desktop

Desktop
my_new_app.html

What's inside that one file

my_new_app.html
<!DOCTYPE html>
<html>
  <head>
    <style>
      /* your CSS lives here */
      body { background: cream; }
    </style>
  </head>
  <body>
    <h1>My Tool</h1>
    <button>Click</button>

    <script>
      // your JavaScript lives here
      const btn = document.querySelector('button');
      btn.onclick = () => alert('hi');
    </script>
  </body>
</html>
  • This is usually what Gemini Canvas hands you by default.
  • Easiest to share — one file, attach it anywhere.
  • You'll outgrow it when the file gets long, or when you want to reuse the same CSS across multiple pages.
Path B — when one file gets messy

A folder of three files.

Split the layers into separate files. The HTML file then "links to" the CSS and JS files so the browser knows where to find them. This is the shape every real website uses.

What it looks like inside the folder

my_new_app/
index.html
style.css
script.js

Or written out as a tree

my_new_app/
my_new_app/ index.html style.css script.js

How they connect: two short lines inside index.html tell the browser to load the other two files.

inside index.html
<link rel="stylesheet" href="style.css">
<script src="script.js" defer></script>
  • Cleaner once the project is more than ~100 lines.
  • You can change just the CSS without scrolling past the HTML.
  • Easier for an AI coding helper like Claude Code or Cursor to work with.
The paper-cut: saving with the right extension.

Notepad and TextEdit will try to save your file as .txt by default. You have to override that, or the browser won't know it's a web page.

  • TextEdit (Mac): Format → Make Plain Text first. Then in the Save dialog, uncheck "If no extension is provided, use .txt" and type the full filename like index.html.
  • Notepad (Windows): In the Save dialog, change "Save as type" to All Files, then type the full filename like index.html.
  • Easier route: install VS Code. It treats every file as code by default — no fighting with the editor.

A handful of file extensions you'll see, in plain English: .html is a web page, .css is styling, .js is JavaScript, .png or .jpg is an image, .md is plain-text notes (often used for a project's README), .json is structured data the AI sometimes asks you to save alongside.

The two G words

Git and GitHub, in two paragraphs.

Two different tools, often confused. You only need to understand them at this level to get going.

Git is a program that runs on your computer. Every time you save your project, Git takes a snapshot — so a week from now you can see what you changed, undo something, or recover a version that worked before you broke it. It's free, it's small, and it works without the internet. You install it once and forget about it.

GitHub is a website that holds a copy of your project online. It mirrors what's on your computer, so other people can see your code and so you don't lose everything if your laptop dies. GitHub also has a free feature called GitHub Pages: take the HTML files in your project, flip a switch, and GitHub publishes them at a real web address. That's how my taskFlow lives on the internet — it's a folder on my computer, mirrored to GitHub, served by GitHub Pages. No server. No database. Just files.

If GitHub is blocked.

You can still learn the shape of the work: ask clearly, inspect the files, save versions, and test a small prototype. Deployment is partly an infrastructure question. The skill is knowing what is possible and how to make a working first version inside the tools you can access.

WCAG 2.1 AA

Make it usable for everyone.

If you're going to put something in front of students, run these five checks. The AI won't always do them by default.

  • Color contrast of at least 4.5:1.

    Body text needs to be dark enough against its background. Paste your text color and background color into the WebAIM contrast checker — it tells you in two seconds whether you pass.

  • Alt text on every meaningful image.

    Every image that carries meaning gets an alt attribute describing it. Purely decorative images get alt="". Screen readers depend on this.

  • Reachable with the keyboard.

    Try pressing Tab to move through your tool without using a mouse. Can you reach every button, link, and form field? Can you submit the form with Enter?

  • Visible focus rings.

    When you tab to something, you should see a clear outline around it. If the AI stripped the default outlines to "look cleaner," ask it to put them back.

  • Real semantic HTML.

    Buttons should be <button>, not <div>. Headings in order — h1, then h2, then h3. Form fields need <label> elements. Screen readers and keyboard users depend on this.

The accessibility prompt.

"Audit this for WCAG 2.1 AA. Check every text/background color pair for at least 4.5:1 contrast. Add alt text to every meaningful image. Make sure every interactive element is keyboard-reachable. Keep visible focus styles. Use semantic HTML elements — real buttons, labels, and headings in order."

Copy and adapt

Prompt recipes.

Use these when you don't know where to start. Adapt the words to your situation.

Start a simple classroom tool

"Create a single-file HTML web tool for vocabulary practice. Students see one term at a time, guess the definition, click to reveal the answer, and the page tracks how many they got right. Clean and readable for middle school. Use warm neutral colors. Not childish."

Ask for a multi-file project (not one big file)

"Create a Todo List app. Put the code into three separate files: index.html for the page structure, style.css for the styling, and script.js for the JavaScript logic. The JS should let me add a todo, mark it done with a strikethrough, and remove it. Use Tailwind CSS and Lucide icons."

Build a real game with HTML <canvas>

"Create a simple game using an HTML <canvas>. Make a small red square I can move with the arrow keys. Add a blue square at a random location. When the red square touches the blue one, the score goes up by one and the blue square jumps to a new random spot. Show the score in the corner."

Build a diagram or board game with SVG

"Create a 3x3 tic-tac-toe board using SVG, not <canvas>. When I click a square, draw an X in it. Then the computer draws an O in a random empty square. Use clear lines, good spacing, and label the winner when the game ends."

Make it remember things

"Add localStorage so entries persist between page refreshes. Save them under a key like evidence-entries. Load them on page load and display them on the page in the order they were added."

Redesign the look

"This works but it looks generic. Restyle it. Warm cream background. Terracotta and sage accents. Newsreader serif for headings. Space Grotesk for body. Generous spacing. Rounded corners. Soft shadows. Calm and professional — not childish, not corporate."

Audit it for accessibility

"Audit this for WCAG 2.1 AA. Check every text/background color pair for at least 4.5:1 contrast. Add alt text to every meaningful image. Make sure every interactive element is keyboard-reachable. Keep visible focus styles. Use semantic HTML elements."

Debug something that's broken

"The Add button doesn't create a new card when I click it. Read the code, explain the likely cause in plain language, then give me a corrected full file."

Help me think about what to build next

"I'm a [grade and subject] teacher. I keep wishing I had a tool that [describe the friction]. I'm not a developer, but I want to make a small first version with HTML, CSS, and JavaScript. Help me think about the smallest version that would still be useful, then build version one."
