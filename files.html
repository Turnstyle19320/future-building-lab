How web projects are organized

File Structures

A single HTML file is fine for the first win. Separate files become useful when the project needs to be easier to edit, share, debug, and deploy.

Single file

Everything lives in one `.html` file: structure, style, and behavior.

evidence-dashboard.html

Best for demos, Google Sites embeds, one-page tools, and first attempts.

Multi-file

The project gets separated into clear parts.

my-tool/
  index.html
  style.css
  script.js
  assets/
    hero.png

Best for GitHub Pages, larger projects, reusable assets, and agent-assisted editing.

HTML

The structure

Headings, forms, buttons, links, sections, and the words people see.

CSS

The appearance

Color, typography, spacing, layout, visual hierarchy, and responsiveness.

JavaScript

The behavior

What happens when someone clicks, types, saves, filters, sorts, or navigates.

When to move into VS Code

Use an IDE when copy-paste starts costing you time.

You have more than one file

Folders, assets, and reusable styles are easier to manage locally.

You want an agent to edit across files

Codex, Claude, or another coding agent can inspect the project, make patches, and explain tradeoffs.

You need version history

Git lets you try changes without losing the last working version.
